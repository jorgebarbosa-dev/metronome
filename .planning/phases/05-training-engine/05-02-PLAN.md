## Current Scheduler State

The existing scheduler (`src/audio/scheduler.ts`) has:
- `start(bpm, timeSignature, accentEnabled, volume, soundConfig?, subdivision?)`
- `stop()`
- `updateConfig(partialConfig)`
- `isRunning()`
- Internal `currentBeat` tracking (1-based within bar)
- `setInterval(schedule, 25)` for lookahead polling
- `playClick()` for each beat/sub-beat
- `onBeatScheduled` callback for visual feedback

## Key Technical Constraints

- **NEVER use setInterval/setTimeout for audio timing** — the existing `setInterval` is ONLY for lookahead polling, not for timing audio events
- Audio events are scheduled using `audioContext.currentTime + offset`
- Beat callback fires for visual feedback

## Mode Combination Logic

**Count-in behavior:**
- If enabled, scheduler starts in count-in phase
- Plays `countIn.measures` bars with full audio
- After count-in, transitions to `playing` phase
- Bar counter resets to 1 after count-in

**Silence behavior:**
- If enabled, alternates between play and silence bars
- During silence bars: skip `playClick()` but still call `onBeatScheduled`
- Phase switches when `silenceBarsRemaining` reaches 0

**Auto-BPM behavior:**
- If enabled, uses `startBpm` as initial BPM (not current metronome BPM)
- Every `everyNBars` bars, increment BPM by `increment`
- Cap at `targetBpm`
- When target reached, stay at target

**Combined behavior:**
1. Start → if count-in enabled, enter count-in phase
2. Count-in ends → enter playing phase with all active modes
3. During playing: silence and auto-BPM operate independently
4. Auto-BPM changes BPM at bar boundaries (affects scheduling immediately via `updateConfig`)
