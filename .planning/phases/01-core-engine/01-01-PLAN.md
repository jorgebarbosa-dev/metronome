## Critical Technical Constraints

- **NEVER use setInterval/setTimeout for audio timing** — always schedule via Web Audio API's AudioContext.currentTime
- AudioContext must be resumed on first user gesture (browser autoplay policy)
- Square wave oscillator for percussive click sound per D-02
- Accented beat uses higher frequency than unaccented per D-03
- Short percussive envelope (attack ~1ms, decay ~50-100ms) per D-04 discretion
- Lookahead: check every 25ms, schedule next 100ms of beats per research

  <action>
    Create `src/audio/scheduler.ts` that implements the lookahead scheduling pattern:

    1. Export `createScheduler(audioEngine, onBeatScheduled?)` returning a scheduler object with:
       - `start(bpm, timeSignature, accentEnabled, volume, soundConfig)` — begins scheduling
       - `stop()` — stops scheduling and clears any pending intervals
       - `updateConfig(partialConfig)` — updates BPM, timeSignature, accentEnabled, volume, or soundConfig mid-playback
       - `isRunning()` — boolean state
    
    2. Implementation details:
       - Use `setInterval` with 25ms interval ONLY for the lookahead check (NOT for playing audio)
       - Maintain `nextNoteTime` as the AudioContext time when the next beat should play
       - Maintain `currentBeat` as 1-indexed beat number within the current measure
       - In each interval tick:
         a. While `nextNoteTime < audioContext.currentTime + 0.1` (100ms lookahead window):
            - Schedule the beat: call `playClick(audioEngine.context, audioEngine.context.destination, config, isAccent, volume, nextNoteTime)`
            - Call `onBeatScheduled({ beatNumber: currentBeat, isAccent, scheduledTime: nextNoteTime })` if provided
            - Advance `nextNoteTime` by `60 / bpm` seconds
            - Increment `currentBeat`, wrap to 1 after reaching `timeSignature.beats`
            - Determine `isAccent = accentEnabled && currentBeat === 1`
       - Store interval ID and clear it on `stop()`
       - When `updateConfig` is called with new BPM: do NOT reset `nextNoteTime` or `currentBeat` — just update the interval timing going forward
    
    3. Critical requirements:
       - The ONLY setInterval in the codebase is this 25ms check interval
       - All audio is scheduled via `audioContext.currentTime + offset`, never via setInterval callback directly
       - `stop()` must cleanly clear the interval and reset state
       - `nextNoteTime` must be initialized to `audioContext.currentTime + 0.05` (50ms) when starting to avoid scheduling in the past
  </action>
